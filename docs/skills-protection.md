# Skills 与系统提示词保护方案

> 本文是产品架构说明，不构成法律意见。若 Skills 或提示词包含受版权、商业秘密、合同或其他权利保护的内容，应由权利人和专业顾问结合具体授权文本进行判断。

## 结论先说

如果四个 Agent 的完整系统提示词和 220 个 Skills 随 Electron 桌面程序一起下发，**不能承诺用户无法获取**。当前版本为了支持本地运行，确实将这些运行时资源打进安装包；有技术能力的用户可以复制安装目录、读取归档或调试进程。因此，单纯依靠隐藏菜单、改文件名、ASAR、代码混淆或本地加密，只能提高提取成本，不能提供真正的保密边界。

Electron 官方文档说明，ASAR 是 Electron 应用的归档格式，主要用于缓解 Windows 路径问题、提升加载体验和遮挡一般性的直接查看；Node API 仍然可以把 ASAR 当作虚拟目录读取，官方文档还提供了列出和读取归档内容的示例。[1]

## 当前 2.0.4 的暴露情况

| 资产 | 当前状态 | 结论 |
| --- | --- | --- |
| 四个 Agent 的 `agent.cordis.yml` | 跟踪在仓库中，并随 `bundled/**` 打包 | 仓库协作者可直接读取；安装用户可通过分析安装目录或运行时获取 |
| 220 个 `SKILL.md` | 跟踪在仓库中，并随 `bundled/**` 打包 | 不能视为客户端秘密 |
| 通用 Agent 隐藏逻辑 | 仅隐藏用户界面入口 | 不是访问控制，不能保护源文件 |
| Electron ASAR / `asarUnpack` | 用于发布和运行时兼容 | 不是加密容器，也不是防提取方案 |
| 私有 GitHub 仓库 | 当前仓库为私有 | 可限制普通 GitHub 访客访问源代码，但不能阻止已获得安装包的用户分析本地资源 |

## 推荐方案：服务端执行，客户端只做工作台

若目标是“用户可以使用，但不直接获得核心 Skills 和系统提示词”，建议把产品拆成两层。桌面端保留安装、登录、会话界面、文件选择、脱敏提醒、请求协议和结果展示；服务端保留四个 Agent 的完整提示词、Skills、模型调用、版本控制、访问策略和审计日志。客户端提交经过认证的任务，服务端在内部加载对应 Agent 和 Skills，完成模型调用后只返回结果、引用和结构化风险清单。

```text
Windows 桌面端
  ├─ 登录 / 设备绑定 / 会话界面
  ├─ 文件脱敏与上传确认
  └─ HTTPS 请求 + 短期访问令牌
          │
          ▼
受控法律 AI 服务
  ├─ Agent 提示词与 Skills（不下发）
  ├─ 模型调用与版本管理
  ├─ 租户隔离、配额与权限
  ├─ 审计、告警、撤销和轮换
  └─ 返回回答、风险清单和待核验事项
```

服务端应使用短期令牌、最小权限、租户隔离、传输加密、访问审计和可撤销的会话机制。OWASP 的 Secrets Management Cheat Sheet 将集中管理、细粒度访问控制、最小权限、生命周期管理、审计和轮换列为重要原则。[2]

## 如果必须保持离线运行

离线版可以采取“降低暴露、提高提取成本”的组合措施，但应在产品文档中诚实表述为**防普通用户误操作和降低批量复制风险**，而不是“绝对保密”。可考虑移除公开仓库中的核心内容、把提示词拆分并压缩、使用签名和完整性校验、将低敏感规则与核心规则分离、关闭调试入口、减少敏感日志，并通过许可证和再分发条款明确使用边界。

本地加密只有在解密密钥不与程序同时交付时才有实质意义。如果客户端必须自动解密并使用，攻击者通常可以通过调试、运行时补丁、内存分析或拦截请求取得明文。真正的核心提示词不应与客户端和解密密钥同时下发。

## 建议的发布分层

| 版本 | 交付内容 | 适合目标 |
| --- | --- | --- |
| 开源开发版 | 桌面壳、接口、示例 Agent 和非核心 Skills | 社区协作、插件开发、问题复现 |
| 普通使用版 | 桌面客户端，核心 Agent 和 Skills 在服务端执行 | 企业高管、创业者和业务团队 |
| 私有部署版 | 服务端部署在客户自己的网络或专属云环境 | 对数据驻留、审计和内网隔离有要求的组织 |

## 对本项目的具体建议

当前仓库保持私有是合理的，因为公开仓库会让四个 Agent 配置和 220 个 Skills 直接可见；但这只能保护 GitHub 源码，不能保护随 2.0.4 安装器下发的本地资源。若要继续提供当前离线安装器，应把它定位为“方便使用的本地版”，不要把提示词保密作为安全承诺。

下一阶段若要保护核心资产，建议先建立一个不包含核心提示词的客户端请求协议，再将四个 Agent 和 Skills 迁移到受控服务端；迁移完成并通过权限、日志、断网和更新测试后，再把公开下载入口切换到服务端版本。
