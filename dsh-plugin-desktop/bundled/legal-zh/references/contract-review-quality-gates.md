# 合同审核质量门禁

> 本文件是商业法务合同审查、SaaS/MSA 审查和 DPA 专项审查共同遵循的事实忠实度与交付门禁。它不替代法律研究；实质性法律判断仍须按知识库路由检索并标注依据。

## 0. 唯一事实源与强制路由

凡用户提交合同文件、合同标题、合同条款，或请求“审查这份合同”，先进入合同事实模式。**当前用户文件及用户在本会话中明确提供的事实，是合同事实的唯一来源。**通用合同模板、模型记忆、其他合同、默认阈值和“常见做法”不得补写当前合同事实。法律规则可以来自法律知识或检索，但必须与合同事实分开标注。

固定路由为：文件读取与覆盖确认 → 合同类型与我方角色识别 → 建立合同事实账本 → 供应商协议基础审查 → 命中条件时执行 SaaS/MSA 专项 → 命中条件时执行 DPA/隐私专项 → 事实一致性与引用门禁 → 最终报告或阻断说明。内部至少记录 `document_read`、`contract_type`、`vendor_review`、`saas_review`、`dpa_review`、`quality_gates` 六个状态。报告至少披露合同类型、我方角色、阅读范围、文件读取状态和未提供附件。

## 1. 合同事实账本

正式审查前先建立结构化账本。账本可内部保存，也可在报告中以“事实核对摘要”披露；无账本不得生成貌似完整的合同审查报告。

```json
{
  "document": {
    "name": "",
    "source_id": "",
    "read_status": "complete|partial|failed|empty|unavailable",
    "coverage": "",
    "pages_or_sections_read": "",
    "attachments": [{"name": "", "status": "provided|missing|unreadable", "source": ""}]
  },
  "parties": [{"role": "甲方|乙方|其他", "name": "", "source": "", "status": "confirmed|missing|ambiguous|assumed"}],
  "facts": [{"id": "", "category": "", "value": "", "source": "", "status": "confirmed|missing|ambiguous|assumed"}],
  "routing": {"contract_type": "", "our_role": "customer|vendor|unknown", "vendor_review": "required|skipped|blocked", "saas_review": "required|skipped|blocked", "dpa_review": "required|skipped|blocked"}
}
```

每个事实必须有 `source`。`confirmed` 仅表示当前文件或用户明确输入直接支持；`missing` 表示材料没有提供；`ambiguous` 表示原文存在但含义不清或互相冲突；`assumed` 仅可用于临时模式并须显式披露。除非有新来源，不得将后三种状态改写为确定事实。

核心事实至少覆盖：合同名称、甲乙双方、我方角色、合同期限、金额或金额缺失、付款机制、服务内容、数据处理、知识产权、责任上限、解除机制、争议解决、附件状态。SaaS 另加自动续约、调价公式、数据导出期限、SLA 与补救；DPA 另加处理者角色、处理目的、数据类别、主体类别、处理地点、子处理者、跨境路径、安全事件时限、删除/返还、审计和训练模型用途。

## 2. Gate 1：文件读取与覆盖门禁

路径不存在、上传内容为空、格式解析失败、文件不可读、只读到部分内容但未披露范围，或关键附件未提供却要求对附件作结论，均阻断正式审查。阻断时只能输出读取状态、失败原因、已读取范围和补充材料选项，不得输出完整风险报告。

允许用户重新上传、粘贴正文或明确要求“临时审查”。临时审查必须标记 `[临时模式]`，每个事实标为“基于用户粘贴内容”或 `assumed`/`待核实`，不得声称已完成全文审查。正文引用 DPA、价格表、SLA、服务规格、平台规则或网页政策而附件未提供时，必须写明：**“正文已读；以下附件未提供/未读取，因此相关结论不完整。”**

## 3. Gate 2：事实完整性门禁

正式报告前逐项检查合同名称、双方、我方角色、期限、金额或金额缺失、付款机制、服务内容、数据处理、知识产权、责任上限、解除、争议解决和附件状态。缺失项写入账本并标记 `missing`，不得模板填充；冲突项标记 `ambiguous` 并同时列出两个来源。合同名称、双方、我方角色或阅读范围无法确认时阻断正式报告；其他缺失项可继续，但须在报告顶部和待核实清单披露。

## 4. Gate 3：真实条款引用门禁

每个高风险或高商业/操作摩擦发现必须包含真实条款号、来自当前文件的原文短引、事实状态、风险点、触发条件、可能后果、建议修改和不让步时的处理。无法填入真实条款号和原文的内容只能进入“材料缺失/待核实事项”，不能放入“合同说”。

| 指标 | 最低要求 |
|---|---:|
| 高风险问题真实条款引用率 | 100% |
| 高风险问题原文可回指率 | 100% |
| 报告新增金额、日期、百分比账本覆盖率 | 100% |
| 未声明的“原文示例”比例 | 0% |
| 未提供附件却声称完整审查比例 | 0% |

带引号的内容只有在当前文件逐字存在，或明确标注“非本合同原文的通用示例”时才能使用；`合同说`区块禁止使用通用示例替代原文。

## 5. Gate 4：反模板污染与关键事实一致性

交付前抽取报告中的实体、金额、日期、百分比、期限、付款方式、SLA、责任上限、条款号、附件名称和原文引句，逐项与事实账本、当前文件或用户明确输入比对。合同没有 50%+50%付款却输出该付款方式、合同为 99.0% SLA 却输出 99.9%、合同没有共同所有却写成共同所有、附件未提供却声称“附件一规定”、已明确当事人却写“甲乙方待定”、以“原文示例”替代真实引用，均为阻断模式。

发现不一致时，删除该事实，改为 `missing`/`ambiguous`/`待核实`，或返回事实校验失败项；不得以“通常”“例如”掩盖一个看似描述当前合同的确定断言。

## 6. Gate 5：法律结论与谈判立场门禁

合同事实必须绑定账本状态和来源；法律结论必须说明法域、依据、事实前提和核验状态；谈判立场必须写成“我方建议/目标/底线/可让步方案”，不得冒充法律必然结论；需要律师裁量的事项就地标记 `[需审查]`。除非当前合同原文和适用法律均支持，否则“数据所有权完全归甲方”“全部间接损失无上限”“违约金为合同总额 30%”只能作为谈判目标、风险描述或待判断事项。

## 7. Gate 6：交付前三问

最终输出前必须回答：

1. 我写出的每个关键事实，是否都能回指当前文件中的条款或用户明确输入？
2. 我引用的每个条款号和原文，是否在当前文件中真实存在？
3. 我是否把缺失附件、歧义条款或临时假设写成了确定事实？

三个答案必须都是“是”。任一答案为“否”，不得交付完整审查报告；应展示失败项并要求用户确认或补充材料。

## 8. 逐条输出契约

没有真实条款号和原文的内容不得套用以下结构：

```markdown
### [真实条款号] [风险名称]
**合同说：**
> [当前文件中的逐字或忠实短引]
**事实状态：** [已确认 / 存在歧义 / 材料缺失]
**来源位置：** [页码、条款号、段落或附件名]
**风险点：** [具体问题]
**触发条件：** [何时发生]
**可能后果：** [付款、数据、责任、经营或争议后果]
**法律风险：** [🔴/🟠/🟡/🟢]
**商业/操作摩擦：** [🔴/🟠/🟡/🟢]
**建议修改：**
> [最小可谈判或修订语言]
**若对方不让步：** [替代方案或上报事项]
```

通用风险可单独放在“通用风险提示”中，并明确写“不是本合同原文”；不得混入“合同说”。

## 9. 交付前最小检查清单

- [ ] 读取状态、覆盖范围和附件状态已披露。
- [ ] 事实账本已建立，所有 `confirmed` 事实有来源。
- [ ] 核心事实缺失或冲突未被模板填充。
- [ ] 每个高风险问题均有真实条款号和原文短引。
- [ ] 报告内新增数字、日期、百分比和实体可回指账本。
- [ ] 法律结论、谈判立场和待律师判断已分开。
- [ ] Gate 1 至 Gate 6 全部通过；否则输出阻断说明而非完整报告。

## 1. 效力审查门禁

审核任何合同前，优先核查以下效力风险：

1. **名实不符交易**：循环买卖、合作开发、投资、委托贷款等安排是否实为借贷或其他法律关系
2. **关联交易公允性**：是否存在明显不合理低价、关联输送或恶意串通风险
3. **格式条款**：是否免除己方责任、排除对方主要权利，是否已履行提示说明义务
4. **审批登记**：区分合同效力、报批义务和物权变动，不把未登记简单等同于合同无效
5. **合同成立要素**：当事人、标的、数量是否明确；鉴于条款中的事实陈述是否会形成禁止反言风险

**发现效力风险时，先处理效力问题，再谈条款优化。**

---

## 2. 主体与授权门禁

必须核查：

- 签约主体是否适格，名称与证照是否一致
- 法定代表人签字是否同时加盖公司公章
- 非法定代表人签字时是否有有效授权委托书
- 项目部章、业务章、个人签字是否可能引发表见代理争议
- 对方是否为一人公司、关联公司、减资公司或提供担保主体
- 涉及担保时是否需要股东会或董事会决议及附件留存

## 3. 条款审查门禁

逐条审核时至少核查以下八个维度：

| 维度 | 核查要点 |
|------|---------|
| **价款与支付** | 付款节点、发票、结算、唯一收款账户、非指定账户付款后果 |
| **交付与验收** | 交付标准、验收程序、异议期、逾期未异议后果 |
| **违约责任** | 违约情形是否覆盖关键风险，违约金是否合理，实现债权费用是否由违约方承担 |
| **解除与清算** | 解除权触发条件、解除后返还/结算/赔偿安排是否明确 |
| **担保与保险** | 抵押/质押登记义务、保证期间、最高额范围、担保解除条件 |
| **送达与争议解决** | 送达地址、电子送达、变更通知、法院/仲裁机构是否明确且有利 |
| **定义与附件** | 定义不承载具体权利义务，内部制度应转化为合同附件 |
| **内部一致性** | 正文与附件、通用条款与特别约定、金额数量、期限条件、定义用法之间不得冲突 |

## 4. 修订方式路由决策树

逐条审核意见在写入批注或执行修订之前，必须按以下决策树确定修订方式：

### 4.1 决策树

```
审核发现 → 这是什么类型的问题？
│
├─ 错别字/笔误/标点/日期格式/法律名称过时
│  └─ 【直接修订】文本替换
│
├─ 对我方有利且可直接落地的增补条款
│  ├─ 实现债权费用不完整 → 【直接修订】补充
│  ├─ 缺少送达确认条款 → 【直接修订】插入标准模板
│  ├─ 缺少声明与保证条款 → 【直接修订】插入
│  ├─ 缺少反商业贿赂条款 → 【直接修订】插入
│  ├─ 缺少限制收款方式条款 → 【直接修订】插入
│  ├─ 签章条款不完整 → 【直接修订】
│  ├─ 缺少独立关系声明 → 【直接修订】插入
│  └─ 银行名称/公司名称错误 → 【直接修订】
│
├─ 合同核心结构不对等（框架审阅发现）
│  ├─ 不对等对我方有利 → 不修改（保留优势），进入逐条审核
│  ├─ 不对等对我方不利：
│  │  ├─ 义务单向性 → 【直接修订】对称化为双方义务
│  │  ├─ 退出权不对等 → 【直接修订】复制为双方对等保护
│  │  ├─ 虚假前提 → 【直接修订】写入我方约束条件
│  │  ├─ 违约责任严重不对等 → 【直接修订】统一化为对等损害赔偿
│  │  └─ 预约合同约束力过强而客户履约能力不足 → 【直接修订】降级承诺、增加防御层
│
├─ 条款矛盾/文本不一致
│  └─ 【批注】指出矛盾位置，给出倾向性建议
│
├─ 商业取舍/重大风险/对方可能不接受
│  ├─ 验收标准重构 → 【批注】给出完整建议文本
│  ├─ 违约金数额调整 → 【批注】列出方案，客户选择
│  ├─ 知识产权归属重大调整 → 【批注】列出方案
│  ├─ 付款比例调整 → 【批注】说明风险，客户决定
│  └─ 默示同意条款修改 → 【批注】说明风险和建议
│
├─ 事实待核
│  └─ 【批注】标注待核实事项
│
└─ 多方案需客户选择
   └─ 【批注】列出方案，标注倾向
```

### 4.2 自检四问（每条审核意见必问）

在确定修订方式前，逐条回答：

1. **"这个问题我能替客户直接改吗？"** → 能 → 直接修订
2. **"这个改动涉及商业判断吗？"** → 是 → 批注
3. **"对方大概率会接受这个改动吗？"** → 是 → 直接修订（但标注告知客户）
4. **"这个改动有多个合理方案吗？"** → 是 → 批注，列出方案

## 5. 终稿三件套

合同审核的最终交付物应为三件套：

| 交付物 | 内容 | 受众 |
|--------|------|------|
| **批注版合同** | 逐条修订痕迹 + 批注说明 | 律师/法务（内部审查） |
| **法律意见书** | 结构化法律意见：总体评价 → 主要风险 → 修改建议 → 签约建议 | 客户/业务方 |
| **法律分析** | 详细法律依据、类案参考、风险六维度评价 | 律师/法务（内部存档） |

---

## 6. 风险提示四要素

发现风险时必须说明：

1. **风险点是什么**
2. **风险如何触发**（在什么条件下会变成实际损失）
3. **可能导致什么后果**
4. **应如何修改**（给出具体修改建议，不只是"建议修改"）

## 7. 特殊合同类型注意

| 合同类型 | 额外关注 |
|---------|---------|
| 建设工程合同 | 工期顺延、工程变更、竣工验收、结算审计、优先受偿权 |
| 房地产交易 | 产权瑕疵、土地性质、规划变更、交付标准、面积差异处理 |
| 股权投资 | 估值调整（对赌）、优先权、退出机制、陈述保证、竞业限制 |
| 融资合同 | 利率合规、担保安排、提前到期条款、交叉违约 |
| 技术合同 | 知识产权归属、保密范围、技术标准、二次开发权利 |
