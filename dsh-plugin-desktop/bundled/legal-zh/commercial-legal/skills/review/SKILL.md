# /review

根据审查指引审查接收方协议。从标题识别协议结构，选择合适的技能，如 `confirm_routing` 启用则在继续前与用户确认。任何合同审查都必须先通过文件读取与覆盖门禁、建立合同事实账本，再进行专项路由；路由或事实门禁失败时不得生成完整备忘录。

## 指令

1. **加载审查指引。** 如果存在占位符，停止并提示运行 `/commercial-legal:cold-start-interview`。同时读取 `## 审查偏好` → `confirm_routing`。

2. **获取协议：** 从文件路径、云文档链接、合同管理系统ID或粘贴文本获取。记录 `source_id`、解析状态、阅读范围和附件清单。路径不存在、内容为空、解析失败或只读部分时，阻断正式审查；只有用户明确选择 `[临时模式]` 才可继续。

3. **先建立事实账本，再读取结构。** 将合同名称、甲乙双方、我方角色、期限、金额/金额缺失、付款机制、服务内容、数据处理、知识产权、责任上限、解除、争议解决和附件状态写入账本；每项绑定来源和 `confirmed/missing/ambiguous/assumed` 状态。缺失和歧义不得由模板补全。

4. **读取文件结构——先看标题。** 提取主协议标题和全部展示件/附件标题。这是路由信号。

5. **根据文件结构选择技能。** 固定执行：文件读取与覆盖确认 → 合同类型识别 → 供应商协议基础审查 → 命中订阅/平台/云服务/自动续约/周期费用时叠加 SaaS 审查 → 命中个人信息/客户数据/跨境/再处理者/训练模型时叠加 DPA/隐私审查 → 事实一致性门禁。

   | 文件/条款标题包含 | 技能 |
   |---|---|
   | 保密协议、NDA、保密协议书（作为*主*协议） | **保密协议审查** |
   | 主服务协议、专业服务、工作说明书、咨询服务协议 | **供应商协议审查** |
   | 订阅、SaaS、云服务、带自动续约的订单、带周期性费用的软件许可 | **SaaS审查**（叠加于供应商协议审查之上） |
   | 数据处理协议、DPA（作为展示件或独立文件） | **DPA/隐私专项审查**（与基础审查共享事实账本） |

   多个技能可适用。常见组合：MSA + SaaS + DPA 展示件 → 供应商协议审查，叠加 SaaS 与 DPA 专项；缺失附件不得合并为“完整合同已读”。

6. **如果启用，确认路由。** 如果 `confirm_routing` 为 `true`：

   ```
   我将按以下方式审查：[协议类型]。
   
   已识别文件：
   - [主协议标题] → [技能]
   - [展示件A标题] → [如何处理]
   
   是否正确？（是/否——或告诉我哪里不对）
   ```

   等待确认。如果 `confirm_routing` 为 `false`：无声继续。

7. **运行技能。** 完全执行每个技能的工作流。如多个技能适用，依次运行并将输出整合为单一备忘录。内部记录 `document_read`、`contract_type`、`vendor_review`、`saas_review`、`dpa_review`、`quality_gates` 状态；每个专项结果保留事实来源和附件状态。

8. **交付前执行质量门禁。** 逐项核对报告中的实体、金额、日期、百分比、条款号、原文和附件是否存在于事实账本或当前文件；高风险问题真实条款引用率必须为100%；回答 Gate 6 三问。任一失败时输出校验失败项/待补材料，不得交付完整报告。

9. **检查上报：** 如果任何问题超出审查者权限，调用**上报标注器**路由并起草上报说明。

10. **提供后续操作：** 给业务负责人的利益方摘要、带修订痕迹的.docx、合同管理系统记录创建、加入续约登记册。

## 示例

```
/commercial-legal:review vendor-msa.pdf
/commercial-legal:review https://drive.google.com/file/d/ABC123
/commercial-legal:review
[粘贴协议文本]
```

## 输出

按技能格式的完整审查备忘录。路由决定记录在顶部。逐条偏离、具体修订语言、具名审批人。
